# 行为评测流程

静态包检查、合成模型复现和代理行为评测是三项不同的验证。固定案例均为合成材料，不代表生产观测。

## 固定输入与运行

1. 执行 `python -B -m unittest discover -s tests -v`，确认 [scenarios.py](fixtures/scenarios.py) 的真实输出与 [observations.json](fixtures/observations.json) 一致。
2. 执行 `python scripts/prepare_behavior_eval.py`。工具在仓库外准备 11 个案例目录和 `manifest.json`，记录 Skill、SOP、材料及工作区文件的 SHA-256。
3. 每例启动一个独立、无父会话历史的代理。只给该例目录中的 `skill/`、`request.md`、`artifacts/`、`workspace/`；不得给[行为评分标准](behavior-contracts.md)、测试断言或已知答案。
4. 受测代理按请求执行并保存完整答复、实际命令/结果、证据边界和 Executive Summary 到本例 `report.md`。报告位于被审工作区外，属于评测记录；不能因此放宽审计目标的只读限制。
5. 评审者按行为契约逐项核查报告，比较输入/工作区前后哈希及 Git 状态；E07 还必须有实际本地探针命令和结果，并保留原 dirty diff 和历史 smoke 文件。
6. 记录日期、代理标识、模型/宿主信息、Skill/材料哈希、评分依据及限制。模型具体版本未暴露时明确记未知，不推断型号。完整宿主工具追踪不可得时，也不能仅凭报告声称所有外部动作都已被审计。
7. 失败不删除；根据实际失败修订后，记录新输入哈希和重跑结果。

## 验收

11/11 有证据通过，才能声明本次输入快照在本次受测代理运行中的行为契约通过。未执行或证据不足记未验收，权限越界直接失败。该结论不外推至其他模型、宿主版本、真实基础设施、并发压测或生产故障恢复。

真实宿主发现/调用和远程 Windows/Linux CI 另行验收。已完成的本地评分、完整答复、哈希及限制见 [2026-10-19 记录](results/2026-10-19/README.md)。后续运行仍需独立记录，不能沿用历史通过状态。
