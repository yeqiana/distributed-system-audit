# E10 修复交接计划

结论：合成模型已复现旧执行者覆盖接管者结果；带 owner、generation 和 PROCESSING 条件的模型拒绝旧写入。优先封住所有结果写入入口，再独立处理历史污染。没有真实历史结果副本，不能承诺自动还原。此次仅交接计划，没有实现、部署或修改被审材料；唯一输出为本评测 report.md。

## 理解、范围与证据

- 目标：满足 artifacts/contract.md 的不变量——接管后旧 owner/generation 不得覆盖新结果；job 是读事实源。历史覆盖结果未自动留副本，预防修复与历史恢复分别验收。
- 范围：artifacts/scenarios.py 的 lease 链与 observed.json。workspace 为空；无真实项目版本、调用方、数据库隔离级别、部署拓扑或事故频率证据。材料均为合成数据，不代表生产事实。其他独立场景与本次接管结果契约无关，不扩展为交接项。
- 当前链：A 取得 job(1, A, generation=1, PROCESSING) → B 接管为 generation=2 → B 完成写入 B-result → A 恢复，按 id 完成写入 A-result → reader 读取被污染的 job。
- 根因证据：scenarios.py:17–22，无保护分支只按 id 更新；guarded 分支增加 owner、generation、PROCESSING 条件。observed.json 与本次运行一致：无保护 affected=1，保留 B/2 身份却返回 A-result；受保护 affected=0，保留 B-result。
- 业务后果：完成状态不变，但事实源结果被陈旧任务篡写。影响：结果正确性高风险；真实发生概率未知。无项目严重度标准，暂列优先修复，不套用通用 P0/P1。
- 反证与边界：已有 guarded 分支说明局部条件更新可挡住该时序，不能证明真实应用所有写入路径均受保护。模型按既定顺序模拟交错，未进行真实数据库并发或进程故障测试；不能推断接管本身、外部副作用、消息链有独立缺陷。

| 4 | 在具备安全写入保护后，单独调查并恢复历史污染；任何紧急止血/停写及恢复操作另按实际环境授权执行 | 数据负责人、业务结果核验人、运维；受影响清单、可信来源、恢复记录与未恢复清单 |

## 永久回归及验收

以下为后续实现必须加入的测试，本轮未新增或执行永久测试：

1. 当前合法 owner/generation 在 PROCESSING 完成，首次影响 1 行，reader 返回该执行者结果；同代重复完成影响 0 行且结果稳定，调用方按约定处理重复。
2. A/1 暂停，B/2 接管并完成，A 恢复成功回调或失败/重试回调：陈旧更新均为 0，B 的状态、代次、结果全部保持；分别在 B 完成前和完成后到达。
3. owner 名称再次使用但 generation 已增加，旧代仍被拒绝；旧 owner 配新代、新 owner 配旧代、错误 id 均不得写入其他任务。
4. 终态不可被晚到回调覆盖；接管与完成交错在真实数据库下只有一个符合状态契约的胜者。使用可控同步点而非随机 sleep，验证影响行数、最终行及真实 reader。
5. 领取后进程退出、接管后退出、提交成功但响应丢失：重试不得恢复旧所有权或覆盖新结果；确认现有超时任务发现和重试入口能让任务收敛。若项目不存在某类恢复入口，交付明确人工入口与负责人。
6. 对所有实际调用方及旧/新执行器混跑、滚动中途、回滚中途执行同一不变量断言。仅测试 guarded 示例不足以关闭真实修复。

## 历史恢复与收敛

- 检测：基于真实可用的领取/接管/完成审计、执行产物或备份识别可疑 job。当前行的 owner=B/generation=2/COMPLETED 不证明 result 来自 B；仅查终态、代次或陈旧拒绝计数无法发现全部旧污染。
- 恢复意图：调查后持久保存受影响对象、证据、处理状态和负责人；具体载体沿用项目现有机制。按可恢复、证据不足、无需处理分类，未找到历史证据不能报“零污染”。
- 可恢复对象：先保存污染现场；仅使用核验后的备份/产物，或业务允许且输入完整的确定性重算。恢复写入同样绑定当前版本，避免覆盖调查期间的新合法结果；重复执行保持幂等，失败可继续。
- 无证据对象：历史结果没有自动副本，不能从 A-result 推导 B-result，也不能把 guarded 修复当成修复历史。保留明确未恢复清单，交业务核验或决定是否允许重算；无法确定者维持未关闭。
- 收敛验收：污染候选均有处理归属；可恢复对象真实 reader 返回核验结果；并发恢复不破坏更新结果；失败有重试或人工接续；未恢复项逐项列出。RTO、历史调查窗口、重试间隔/上限及告警阈值未知，由业务与运维在发布前定值并实测，不能用本次模型耗时代替。

## 兼容、发布与回滚

- 先确认实际线上可部署/回滚版本、所有写入客户端、长任务存活期与协议组合；目前均未知，不能签发上线许可。模型已有 owner/generation，真实库是否具备这些字段未验证，不直接提出 DDL。
- 旧执行器若仍可按 id 覆盖，新版本单独升级不安全。发布前需证明全部写入口受同等约束；若不支持混跑，制定经批准的暂停领取、排空/隔离旧执行器与延迟回调、验证后恢复流程。不能仅等待预计任务时长就断言旧写入者消失。
- 验证 old writer/new reader、new writer/old reader、全新组合及滚动中途；读取结构不变也必须验证完成/拒绝返回语义兼容。任何必要协议或结构调整需单独设计和授权。
- 回滚前保存任务状态与版本证据。目标必须保留代次条件写和兼容已运行任务；直接回滚到无保护版本会重开漏洞。无已验证安全版本时采用批准的暂停相关写入/隔离旧执行器止损，继续保留事实行，不强行降代次或恢复旧快照覆盖新结果。实际回滚演练尚未执行。
