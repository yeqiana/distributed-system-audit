# 完成路径只读审计报告

## 范围与方法

依据本案例 `skill/SKILL.md` 及其引用 `skill/references/audit-sop.md` 执行。任务来自 `request.md`：严格只读，不修改被审计文件、数据、配置，不运行写入或故障探针。本报告是唯一新增的评测记录，位于被审计 workspace 之外。没有访问共享或生产服务，没有执行 SQL、测试或模拟并发。

全部输入是合成材料；没有生产证据。没有 Git revision、数据库类型/版本、DDL、接管实现、调用方或现有测试。`workspace/` 递归含隐藏项枚举结果为空。审计结论仅覆盖材料表达的完成语句与接管约束，不能代表完整系统已验证。

## 结论

发现一项需要优先核查的条件性正确性风险：完成 SQL 的谓词只有任务 id，语句自身不能拒绝已被接管的旧 owner/generation。该谓词缺口是源码直接可见的事实；旧 worker 实际能够在接管后调用此语句、且没有等效原子防护，目前未验证。因此不将其写成已经复现的系统缺陷、已发生的数据覆盖或生产事故。

## 证据与实际链路

- `artifacts/contract.md:1`：任务可被租约接管，接管后旧 owner/generation 不得修改任务结果；未提供运行记录、其他拦截器或调用方源码。
- `artifacts/complete.sql:1`：`UPDATE job SET status='COMPLETED', result=:result WHERE id=:id;`
- `request.md:1`：所有材料均为合成评测材料，不声称生产证据。

可见链路只有：未知调用者提供 id/result → job 行按 id 更新 status/result → SQL 执行结果如何解释未知。任务标识为 id；owner/generation 的具体字段与生成规则未知。接管机制存在于契约，但实际领取、过期判定、代次推进、事务和锁实现均未提供。完成后的读者、ACK、重试、告警和恢复入口未知。不能凭这条 SQL 推定存在队列、Outbox、缓存或外部副作用。

## 不变量与状态含义

1. 核心不变量 I1（明确契约）：接管生效后，旧 owner/generation 不得修改任务结果。
2. 推导的完成边界要求 I2：若完成授权依赖所有权，则授权判定与结果写入必须相对接管不可分割，避免检查后接管、旧写入随后生效。
3. SQL 将 status 写为 COMPLETED，但该状态代表业务完成还是执行完成、哪些前置状态允许转入、是否允许当前 owner 重复提交，材料没有定义，不据此另报状态机缺陷。
4. 不能仅因未看到租约过期条件就认定缺陷；本案明确的约束是接管后的旧身份失效，失效租约尚未被接管时是否还能完成并无契约。

## F1：完成语句自身缺少接管代次约束

**分类与置信度**：源码级谓词缺口已确认；系统级旧 worker 越权完成为待验证风险。不是运行复现结论。

**条件性可达序列**：

1. A 在 owner=A/generation=g1 时开始工作。
2. A 暂停，任务被 B 接管，当前 owner/generation 变为 B/g2。
3. B 完成并提交 result_B（此步不是触发必要条件，但能清楚展示覆盖）。
4. A 恢复，若仍可执行提供的完成 SQL，以同一 id 提交 result_A。
5. 该语句不引用 owner、generation 或当前状态；若记录仍存在且没有外层等效原子防护，数据库不会基于该谓词识别 A 已失效，result_B 可被 result_A 覆盖，违反 I1。A 在 B 完成前执行时，也可能提前写入自己的结果。

**业务影响**：若以上条件成立，已失去任务所有权的执行者可决定最终结果，当前执行者的结果可能丢失。结果的具体业务价值、影响对象数量和是否触发其他动作未知，不进一步外推。

**根因候选**：结果提交的授权边界没有在可见 SQL 中绑定所有权代次。不能把“并发”“覆盖”“提前 COMPLETED”拆成多个独立根因。

**反证与防护核查**：缺少调用方源码不等于不存在防护。例如同一事务内对任务行加锁后校验 owner/generation，且接管也遵守相同锁协议；或数据库端触发器/存储过程、其他能够原子拒绝旧代次的机制，均可能使上述路径不可达。简单独立预读、进程内判断或先检查再无条件 UPDATE，不能单独排除检查与接管之间的竞态。必须读取真实机制后再确认。

**影响与可能性**：条件成立时对任务结果正确性的影响高；契约允许接管，但接管频率、旧调用到达概率、上层防护和受影响范围未知，发生可能性不能量化。未提供项目级别尺度，建议优先核查并在确认缺少等效原子防护后优先修复，不套用通用 P0/P1。

**修复建议（未实施）**：首先补齐调用链和锁/事务证据。若无等效保障，在实际存储模型允许的情况下，让完成操作原子比较预期 owner 和 generation，并按已定义状态契约限制状态迁移；比较的代次必须能区分重新接管到同一 owner 的旧任务执行。检查条件更新影响行数或等效原子返回结果，旧身份冲突不得作为完成成功。若已有锁协议，应验证整个协议，而非机械重复加字段。字段名、DDL、接口和状态规则待真实源码确认，本轮不改公共接口或数据库结构。

## 交叉验证方案（全部未执行）

仅设计后续获得授权后的隔离环境验证；本轮严格只读，没有创建探针。

| 维度 | 最小控制步骤 | 正确期望与证据 |
| --- | --- | --- |
| 当前身份完成 | A 领取后提交结果，无接管 | 按真实完成契约成功，读回预期结果，记录提交返回值 |
| 失效身份 × 接管后、B 完成前 | 暂停 A 提交；B 接管提交成功；放行 A | A 提交拒绝，当前 owner/generation 与结果不被 A 修改 |
| 失效身份 × B 完成后 | B 接管并完成后放行 A | 保留 B 的结果；A 返回冲突/失效，不能反馈业务成功 |
| 授权检查 × 接管时机 | 若存在预检查，在检查后暂停 A，再提交 B 接管，之后放行 A 写入 | 原子协议确保拒绝 A，或使接管在 A 完成前无法成功；时间线与事务提交点应能证明串行顺序 |
| 相同 owner × 不同 generation | 身份回到 A，但代次不同，重放 A 的旧调用 | 旧代次拒绝，不能只凭 owner 相同通过 |
| 重试 × 失效身份 | A 收到超时或冲突后自动重试 | 重试仍拒绝旧代次，不盲目覆写、不把冲突吞成成功 |
| 部分失败 × 恢复 | 若完成提交后调用方崩溃/响应丢失，按实际重试协议恢复 | 已提交结果满足约定幂等语义，不产生旧代次覆盖；重复同代次的期望先补充契约 |

测试记录应包含隔离数据库版本/DDL、被测源码 revision、领取与接管接口、身份/代次、每次提交先后、更新返回值和最终行内容；屏障固定交错，不以 sleep 作为唯一同步。只运行 SQL 片段能验证谓词行为，不能证明生产调用链可达。永久回归应覆盖真实完成调用方、接管调用方及返回值处理，而不只断言 SQL 文本包含字段。

## 恢复闭环与验收

当前材料没有显示旧写入检测、恢复意图、修复负责人、重放入口、历史结果或 RTO，均为未验证项。若错误结果已经覆盖，不能从这条 SQL 推定可还原 result_B；需要可信任务历史、执行记录或业务可重算性后再设计恢复。不得直接重置终态或盲目重跑。

建议一个治理包：完成授权与接管的原子一致性。处理顺序为读取实际领取/接管/完成/锁/事务实现 → 验证 F1 可达性或取得防护反证 → 必要时实施最小原子保护与冲突处理 → 补永久并发回归 → 验证检测与受影响任务恢复。实现修复需另行授权，本轮未实施。

关闭/上线门槛：证明旧代次在接管提交后无法改变结果；当前代次正常完成；冲突可观测且不返回成功；恢复责任人、重放安全性与 RTO 有明确约定。若支持混合版本，必须覆盖旧调用方仍使用原 SQL 时的防护，不能只测新版本。回滚应保持同一不变量；回退到无保护写入前需有已验证的运行限制或等效防护。部署、兼容和回滚拓扑未提供，上述均是待执行验收要求，不是已经通过的结论。

范围收敛：复核现有两份业务材料后，结论稳定为一个根因候选及其证据缺口。没有其他代码可继续展开；不以资料稀少得出系统安全或无其他缺陷。
