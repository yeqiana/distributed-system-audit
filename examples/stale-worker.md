# 示例：旧 worker 覆盖新结果

这是合成示例，用来解释如何输出证据；没有对应生产事故或已执行探针。

## 输入片段

```sql
-- Claim 返回 owner 和 generation；完成路径却只按 id 更新。
UPDATE job SET status = 'COMPLETED', result = :result WHERE id = :id;
```

时序：A claim（generation=1）后暂停 → 租约过期 → B steal（generation=2）→ B 完成 → A 恢复执行完成更新。

## 可接受的审计结论

不变量：所有权被接管后，旧 worker 不得覆盖现任 worker 的终态。

源码风险：所示 SQL 没有 owner/generation 条件。还需核实真实调用路径是否有其他栅栏，以及 A 在终态更新前能否继续到达此 SQL。仅凭片段不能认定生产缺陷，也不能确认严重级别。

最小探针方案：在隔离数据库构建该时序，记录每次 claim 的 generation、更新影响行数和最终结果。正确期望为 A 的终态更新影响 0 行，B 的结果保留。严格只读任务只提交方案，不执行建表或写入。

若探针证实 A 覆盖 B，记录实际测试结果、可达调用方和业务后果，再评 Impact×Likelihood。不要预填“已复现”。

## 治理与验收

修复方向是让终态写入校验当前所有权与代次，并核查同类重试/失败更新。具体条件依实际契约决定，不直接把示例 SQL 当生产补丁。

永久回归覆盖旧 worker、接管后完成、失败重试和重复完成。恢复验收还要说明谁发现已被覆盖的结果、能否安全重放、多久收敛。没有恢复证据就不能仅凭 CAS 修复关闭历史数据问题。

Executive Summary：目标是验证旧 worker 栅栏；改动文件无；当前仅源码风险，探针未执行；必须核实调用链及隔离时序测试；结论为待验证。
